# Roadmap

- **Use it when:** you decide the order of the work for the next months of a product.
- **Not when:** you're slicing one feature or initiative into tickets → `/wow-plan`.
- **Reads:** the outcomes, `docs/opportunities.md`, `docs/product/prd.md`, `docs/tech-debt.md`, `docs/risks.md`.
- **Writes:** `docs/product/roadmap.md`.

## Steps
1. **Outcomes first:** 1–3 outcomes for the period, each with its number.
   - Skip it → a feature list with dates.
2. **Candidates:** the opportunities, the PRD's "should" and "later", tech debt, risks.
3. **Score them in one list:** RICE or cost of delay. Debt and risks compete with features in the same list.
   - Skip it → the loudest request wins.
4. **Now, Next, Later:**
   - **Now:** committed and sliced (`/wow-plan`);
   - **Next:** being discovered;
   - **Later:** ideas.

   No dates beyond Now. Each item names the outcome it moves.
5. **Fit the people you have:** Now fits the team's time, with room left for bugs and debt. Write down how much.
6. **Share it.**
   - STOP: agree with whoever decides. Share Now and Next with users if the roadmap is public (`/wow-comms`).
7. **Review monthly:** move items when the evidence changes.

## Done when
- [ ] the outcomes have numbers
- [ ] Now, Next and Later are written, and each item names its outcome
- [ ] every Now item is sliced
- [ ] the next review date is set

## Concepts if you get stuck
- Outcomes over outputs
- RICE, cost of delay
- Now / Next / Later
